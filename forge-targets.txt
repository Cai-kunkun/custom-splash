# Forge build targets.
#
#   <project> <compile-against> <covered minecraft versions...>
#
# The project directory is versions/<project> and it builds once, declaring the
# whole range in META-INF/mods.toml, so a single jar covers every release listed.
# <compile-against> is the oldest covered release, so the build files and the
# Java level stay the ones that era needs. Project names carry the loader suffix,
# matching the versions/<mc>-forge directories.
#
# Membership is a runtime claim: a Forge jar up to 1.20.4 ships a mixin refmap,
# so every release on a line has to resolve getSplash to the same SRG name. CI's
# "report mixin refmap targets" step prints the name each jar bakes in, and the
# mcp_config mappings give the same answer for a release inside a line.

# ForgeGradle 5, Gradle 7.6.4, Java 8. The MCP-era splash holder is
# net/minecraft/client/util/Splashes with func_215276_a, which the 1.16.1 refmap
# and the 1.16.5 mappings agree on.
1.16.1-forge	1.16.1	1.16.1 1.16.2 1.16.3 1.16.4 1.16.5

# ForgeGradle 5, Java 16. All three Minecraft lines resolve getSplash to
# net/minecraft/client/resources/SplashManager#m_118867_, so one jar covers them
# all. Two independent sources agree at both ends: the refmaps of the 1.17.1,
# 1.18 and 1.19 builds, and the mcp_config mappings for 1.17.1, 1.18.2 and 1.19.4.
# Compiling at Java 16 keeps the class files loadable on the Java 17 releases in
# the line. Note this era returns a plain String; SplashRenderer only arrives in
# 1.20.
1.17.1-forge	1.17.1	1.17.1 1.18 1.18.1 1.18.2 1.19 1.19.1 1.19.2 1.19.3 1.19.4

# ForgeGradle 6, Gradle 8.13, Java 17. getSplash is m_280369_ in 1.20, 1.20.1 and
# 1.20.4, so both ends and the compile release agree.
1.20-forge	1.20	1.20 1.20.1 1.20.2 1.20.3 1.20.4

# ForgeGradle 7, Gradle 9.6.0, Java 21. No refmap at all, so the mixin resolves by
# literal name and the build era is the only constraint.
1.20.6-forge	1.20.6	1.20.6
